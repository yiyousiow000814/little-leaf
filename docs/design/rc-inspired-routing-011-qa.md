## A. 搜索、土地、墙与 footprint

| ID | 合成场景 | 必须验证 |
|---|---|---|
| N01 | 空 8×8 地板：正交、对角、混合、同起终点 | 10/14 成本正确；(0,0)→(3,2) 成本 38；同点明确 found/零成本，非失败 |
| N02 | 固定 seed 小地图穷举及随机家具/墙 | A* 成本与同图 Dijkstra 一致；每段独立校验；稳定重放 |
| N03 | 目标、起点被实体占用或未拥有；不可达房间 | invalid 与 no_path 区分；不生成穿家具终点；预算不足为 pending |
| N04 | A→D 对角，两侧 B/C 分别堵一个、都堵、都通 | 前三种不能直斜走；都通才允许；不能经图外侧格跨未拥有角落 |
| N05 | A-B、A-C、B-D、C-D 四条边分别单独加墙 | 任意一条挡住均禁止该对角步；不把空 diagonal edge key 当通行 |
| N06 | 两面相接墙、T 字墙、半墙、墙端厚度 | 无穿角、穿缝或擦进墙厚；实际线段/净空检查生效 |
| N07 | 固定外壳存在、built_walls 为空 | 仍只能从门或已合法拆除墙段穿过外壳 |
| N08 | 四向门洞及门框附近对角 | 先穿合法门洞再转弯；边中心可通不等于斜切门柱可通 |
| N09 | L 形已拥有土地、未购缺口、公共人行道 | 室内不能借缺口抄近路；只有正式入口连到指定公共通道 |
| N10 | 多格家具四种旋转、地毯叠放 | 完整 footprint 均挡路；地毯保持已定义的可通行行为；不按图片 bounds 判碰撞 |
| N11 | 搜索中家具/墙/目标发生新修订 | 旧结果不能提交；更低 g 的节点正确更新；无陈旧队列条目错胜 |
| N12 | 多个同等目标与多个不同成本目标 | 原业务优先级先选；同等级用路径成本而非点数；确定性平局 |
| N13 | 搜索耗尽预算、取消、目标已取消 | pending 可继续；取消任务不再回调改变新任务；不误报永久无路 |
| N14 | 缓存达到上限、纯颜色变更、几何变更 | 缓存有界；颜色不触发几何重算；实体/土地/门洞变化必失效 |

## B. 座位、工作点和占用权

| ID | 合成场景 | 必须验证 |
|---|---|---|
| T01 | 同一模拟 tick 两顾客争同一餐位 | 一名 live owner；失败者换目标/继续等，不抢走已提交 claim |
| T02 | 顾客仍在街道/停车入口，室内空桌 | 保留现有真实到达后分配规则；不在场外提前保留座位 |
| T03 | 各种旋转椅子，桌面挡住一侧、椅背挡住一侧 | 使用合法接近点和对接；不穿桌；八向路由不创造八向入座动画 |
| T04 | 旧顾客清理未结束，新顾客占用脏餐位 | 一名新 occupant 加一份旧 cleanup；token/盘/款项不混；清完才开始新服务 |
| T05 | 原顾客离席仍贴椅，新顾客尝试坐下；阈值/容量/历史边界 | 距椅中心恰为 0.9、距桌中心恰为 1.3 时不分裂；严格超过两阈值且完成离椅、满足完整 can_split 门槛才释放；账本满 60 或非规范历史交接时原顾客不变；合法离席身体不必走到街口才释放 |
| T06 | 无配桌候位椅、餐椅全部有配桌 | 只使用真正候位椅；不能借餐椅制造第二套占用 |
| T07 | 工作点忙，另一个员工仅需经过同格 | 工作点排他不等于硬墙；路过者有路；真实工作仍只有一个 owner |
| T08 | 厨师出盘、服务员取盘、工作面共享/交接 | 同一盘在原接触点转移一次；无斜角远程取盘、盘消失或复制造菜 |
| T09 | 水槽/饮料/垃圾桶四旋转及不同合法侧面 | 各设备沿用专属合法工作点；无被八方向全局放宽的触及范围 |
| T10 | 收银前后两面、排队票号与一个付款 token | 顾客/员工不交换工作面；付款一次；路过不夺占结账目标 |
| T11 | 旧 token 延迟释放、同资源新 generation 已占用 | 旧任务不能释放新 claim；重复取消/释放幂等 |
| T12 | 取消、关闭、超时、移除角色、无路等待 | 只撤销自己权利；旧 cleanup/停车/手持物/付款事实保留；无传送 |
| T13 | 较早等待者到不了某椅，较晚者能到 | 原已到达公平性仍在；较早不可达者不能阻塞所有桌位 |
| T14 | 门口、单格关键通道、设备面上有候位候选 | 不站在关键通道/服务面；不因改为八方向就错误认定有替代绕路 |

## C. 跟随、软避让、时间和重规划

| ID | 合成场景 | 必须验证 |
|---|---|---|
| M01 | 同地面距离正交/对角；不同缩放 | 地面速度恒定，斜步耗时按 sqrt(2)；相机不改变速度 |
| M02 | 30/60/120 Hz 与大 delta 跨多个短段 | 到达误差在明确容限内；总距离预算一次消费；接触事件一次 |
| M03 | 暂停/恢复、切后台、停车交接同 tick | 暂停不增加耐心/claim 计时；停车交接无额外距离预算 |
| M04 | 单格狭道两人相向、三人汇流、持续新来者 | 无永久互等、无限重算、来回抖动；达到软让行上限后可恢复通行 |
| M05 | 贴墙、门框、桌角时软侧移 | 侧移不进入实体/未拥有地板；净空不足时回到中心线 |
| M06 | 入座/离椅/服务接触前仍有侧移 | 接触时偏移归零；盘/手/设备锚点与权利转移一致 |
| M07 | 行走到拐角时重新分配目标 | 从真实位置合法衔接，不 round 穿墙，不跳格心 |
| M08 | 只在后半段加障碍；无关区域改家具 | 受影响段重新规划；无关变化不让所有人重启路径；无穿墙 shortcut |
| M09 | 非法放置覆盖身体或未来受保护段 | 原子拒绝编辑；不扣费、不保存、不移动角色或吞掉任务 |
| M10 | 软避让无法安全解决拥挤 | 保持安全中心路线，允许短暂视觉重叠；不违背资源排他和静态碰撞 |

## D. 存档与能力边界

每一用例都包括当前模型未被部分修改、源保存字节未被改写的检查。新格式名称/版本只有协调完成后才能填入测试，本文不分配版本号。

| ID | 合成场景 | 必须验证 |
|---|---|---|
| S01 | 所有项目现有支持的历史版本，含 v15，另测 v14 | 支持版本按原规则读；v14 仍拒绝；10a 代码/产物不因本设计变化 |
| S02 | 正宗 reception.v1/v2 中途 cardinal 路线及结构边界 | 点序、origin、index、位置、等待、身份、停车、token 不变；无自动斜连；合法 v1→v2 迁移生成空 departures；v1 携带 departures 字段拒绝；v2 缺少必需 departures 数组拒绝 |
| S03 | 新能力中混合旧 cardinal 与新 octile 路线 | 模式明确、各按自身契约；合法旧路线继续，不重放业务 |
| S04 | 新对角存档交给 v15/v16 旧客户端及旧 reception 消费端 | 不支持则 fail closed；不降级回写，不丢字段；profile/revision/摘要/备份保留 |
| S05 | 原生、Web、Firebase、CrazyGames 新读写往返 | 所有端能力一致；fingerprint/envelope 不被偷偷替换；仅合成/测试环境 |
| S06 | 对角经过一格角障碍、四边墙中任一条、未拥有角落 | 载荷拒绝；不是只有运行时搜索阻挡而读档能绕过 |
| S07 | route_origin 到首点斜穿墙、终点伪造椅例外 | 完整段链拒绝；不能只校验中间点或信任 chair ID |
| S08 | 离席身体中段对角、原 cleanup 先/后结束 | 单身体单身份；cleanup 归属正确；无抢座/付款能力；两种结束顺序均往返 |
| S09 | 新旧混合路线跨停车/公共域交接后保存 | 原合法域边界、一次性交接、正常速度、无额外客流槽位 |
| S10 | NaN/Infinity/巨大数组/重复 claim/错 owner/token | 有界校验、原子拒绝；不部分装载、不清空当前游戏 |
| S11 | 写失败、空间不足、云冲突、pending/choice replay、旧客户端打开新存档 | 正常恢复入口可用；归档路线字节不变、不归一化；JS 与原生均支持前禁止 journal/云写；不覆盖新数据，不暴露原始内部错误 |
| S12 | 身体仍坐着时长时间暂停/离线再读 | 无墙钟过期释放 seat；不让新顾客叠占；旧耐心不重置 |

## E. 整合、像素与性能证据

- 重新执行现有接待、离席身体、直接取餐、旧柜台兼容、清洁、收银、墙/门、土地、家具移动、放置、parking、tutorial、保存/恢复和浏览器套件；不要删掉不方便通过的旧 invariant。
- 对确实被新八方向替代的“路线只能 cardinal”断言，保留历史格式测试并新增版本化断言；不能全局删除旧规则。
- 原生用四向椅/桌/设备、八向行走、两种缩放、桌边/门边交叉角色、取盘/放盘/盆沿洗盘、离席/入座交接截图或短录屏。记录 renderer、viewport、动画 phase 和每帧/片段来源。
- Web 和 CrazyGames 做实际导出、真实浏览器下相同关键动作、存储往返、关闭/刷新/恢复与旧格式拒绝。原生画面不能代替这一步。
- 固定小店/扩店/拥挤店 synthetic 场景，记录 actor 数、格数、设备/硬件、搜索次数、展开节点数、缓存命中、搜索和帧耗时分布、重规划/停让次数、内存峰值。与相同基线和相同负载比较；未取得数据前，不写性能改善百分比。
- 可爱角色方向另有美术验收。两者组合后再次观察遮挡、脚部接地、对接锚点与身体穿墙，不能让新轮廓掩盖导航错误。
