# Fixed dirty-save interval

Game progress uses one five-second automatic schedule on native, ordinary Web and CrazyGames. Successful model changes, manual cleanup and advancing simulation mark progress dirty. Those events do not open a save or reset the clock. A clean slot does nothing; a busy writer, blocked authority or active drag retains dirty work for the next slot. Long frames submit at most one write.

Manual Save, Apply decorating, window close, diagnostic capture and the existing browser lifecycle flush remain immediate requests. Web uses its existing single pending write and coalesced explicit requests. Hide/page termination is still not a synchronous IndexedDB durability promise. CrazyGames SDK acceptance remains distinct from remote cloud confirmation.

Each accepted receipt marks only its submitted generation clean. Newer changes remain dirty and unsaved until a later receipt. Failed writes retain the existing error and dirty state for a five-second retry; account, profile, revision, ownership and recovery blockers are unchanged. Native writes retain the existing validation, temporary-file flush and atomic rename.

The coordinated Decorate transaction implementation must be integrated before this scheduler is activated: active-session saves serialize its baseline, X discards the draft, and Apply ends the session before its immediate request. This scheduler does not change Model.save, session restoration or HUD callbacks.

The active-customer writer/reader access asymmetry is a separate last-good containment fix. Merely changing the interval does not repair it, and refusing an unsafe write does not resolve the underlying placement/reader policy decision. Integration remains a draft until both coordinated boundaries and the exact affected checks are complete.

Focused fixtures retain the existing policy marker and exercise both backends, fixed slots, coalescing, blocked/failed attempts and ordinary Web acknowledgements. Synthetic Source checks do not replace actual Godot or browser qualification. Player-original profiles and production services are outside the preparation scope.
