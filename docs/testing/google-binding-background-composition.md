## Local-mode update regression

The PR156 local-mode early return previously installed binding but omitted the updater. Local play now creates its optional updater before returning, and page exit closes it. The updater explicitly distinguishes local from cloud confirmation: a local durable receipt never claims `cloudConfirmed:true`, and the cloud path still requires its original cloud/session receipt.

Local save-before-update holds the existing guest writer WebLock, commits through the same atomic vault transaction, and rereads/verifies the complete authoritative record. Its one-use ticket binds origin, client identity, profile, revision and digest. Background claims and overlapping saves refuse the update; readiness rereads detect a changed legacy writer. A failed manifest check releases the update lock. Native failure resumes only the same verified local profile/revision; unknown or changed authority stays frozen. Dismissal does not save or navigate, and repeated updates cannot create another save or reload.

Focused coverage extends the existing `tests/firebase_boot_presentation.js`, `tests/update_notice.js`, `tests/google_binding_browser.js` and native `test_update_notice` suite. The browser uses real IndexedDB/WebLocks and the actual local boot/updater with inert Auth boundaries, generated records and a loopback manifest. This is not hosted Google or release acceptance. The earlier diagnostic-export reuse receipt remains historical: the changed native update controller requires its new focused validation and cannot claim the old export as exact source.
