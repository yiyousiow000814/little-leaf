# Starter door follows one floor-grid edge

The included door was centered at z=5.5 but 1.5 tiles wide, so its opening ended at z=4.75 and 6.25. Rendering and collision already used the same opening. The mismatch was between those fractional edges and the protected entrance/landing cells (0,5) and(1,5).

This candidate keeps the center at 5.5 and changes only the free starter aperture to one tile, ending at 5 and 6. CafeFootprint supplies the entrance cell, landing, center, aperture edges/width and outside arrival point. The existing shared opening geometry continues to drive the wall cut, casing, threshold and collisions. Purchased doors retain their existing 0.76-tile product width.

Old saves are validated with their original opening before any migration. Only the exact saved starter signature (id 1, door, shell:west, offset 5.5, width 1.5, paid_cost 0) is eligible. There is no historical edit log, so this check matches the saved geometry; a moved-and-returned door is indistinguishable from one never moved. Identity, host, offset, paid value, wallet, ownership, furniture, staff, guests and routes stay intact. No file is rewritten during loading. Newly saved one-tile starter openings require this updated loader; pre-fix builds only accepted the older starter/product widths, so use an untouched pre-migration save when rolling back the executable.

The migration first checks saved bodies and exit/relocation constraints against the narrower aperture. It also checks every remaining guest route, staff path and relocation route against both new jamb strips, with the existing 0.23-tile actor radius. If any check fails, the old 1.5-tile opening remains. The same save can align on a later load when the crossing has cleared. This avoids moving people, replacing saved routes, refusing an otherwise valid save, or narrowing a door around a person. The rectangular swept-path guard is conservative around the jamb corners and can defer a migration that would have had just enough circular clearance.

## Validation

Run `python tests/run_starter_door_grid_native.py` using Godot 4.6.3. It copies the project and uses a disposable profile containing only synthetic saves. 358 door checks and 180 approved-main checks passed, 538 total. Door cases cover new games, explicit 1.5-tile legacy saves across versions 1/3/5/11/15, both jambs, grid and continuous passage, body clearance, guest/staff/relocation routes and consumed prefixes, unsafe deferral, later safe reload, custom signatures, wallet/attachment/runtime preservation, source-byte preservation and repeated save/load.

Native GL Compatibility captures use the real Main scene with its MinimalStart layout, fixed camera, 1360×880 viewport and synthetic 100,000-coin wallet. Only the three production files differ from approved main. The fresh and old-clear before/after images narrow the same door. Crossing images remain pixel-identical because the saved guest occupies a new jamb strip; guests are hidden by the existing Decorate renderer, and the matching JSON records the exact actor and aperture. `native-comparison.json` records the comparisons and hashes. No player saves were accessed. Native captures produced only the existing software-VSync warning and ObjectDB shutdown warnings.
